## Быстрый старт

### Сервер (Docker)

```bash
cd backend
docker compose up -d --build
```

- API: **http://87.242.87.53:8000** (откройте порт **8000** в фаерволе) или `http://localhost:8000` на самой машине.
- Из корня репозитория: `docker compose up -d --build` (нужен Compose 2.20+).

### Фронтенд (ПК)

```bash
cd frontend
npm install
npm run dev
```

`VITE_API_BASE_URL` уже задан в **`.env.development`** / **`.env.production`** / **`.env.local`** на ваш VPS.

**Только локальный бэкенд** (без VPS): в `frontend/.env.development` замените на `VITE_API_BASE_URL=http://127.0.0.1:8000` или удалите строку (будет прокси `/api` → `127.0.0.1:8000`).

### Вход суперадмина (после первого старта API)

- Пароль: `DemoLegal2026!`

### HTTPS без покупки домена

В `.env` задано `TRAEFIK_API_DOMAIN=87-242-87-53.nip.io` (nip.io резолвится в ваш IP). Профиль:

```bash
cd backend
```

Профили **`traefik`** и **`https`** не включайте вместе (порт 80).

### Полезное

- Docker переопределяет `DATABASE_URL` / Redis на хосты `db` / `redis`.
- Уведомления: Redis + WebSocket `/api/ws/notifications`; при недоступном Redis API не падает.
- По умолчанию мониторинг использует открытый источник КонсультантПлюс (`https://www.consultant.ru/law/review/fed/updprof/`) и преобразует его в изменения законов.
- При необходимости можно переопределить источники через `LAW_CHANGE_SOURCES` (через запятую). Поддерживается JSON-формат с полем `changes`.
- Документы: поддержаны API `POST /documents/upload`, `GET /documents/templates`, `POST /documents/generate` (TXT/DOCX/PDF), `GET /documents`, `GET /documents/{id}/download`, `DELETE /documents/{id}`.

## Юнит-экономика (COGS LLM)

Оценка переменных затрат на GigaChat для одного пользователя в месяц. В расчёт входит только LLM; инфраструктура (VPS, Postgres, Redis) сюда не включена.

### Формула

```text
COGS LLM на пользователя в месяц =
  ответов_в_мес × токенов_на_ответ × (1 − доля_кэша) × цена_токена
```

В конфиге задаётся `GIGACHAT_PRICE_PER_1K_TOKENS` (по умолчанию `0.065` ₽ за 1000 токенов, ориентир GigaChat 2 Lite). Тогда:

```text
цена_токена = GIGACHAT_PRICE_PER_1K_TOKENS / 1000
```

При значении по умолчанию: **0,000065 ₽ за токен**.

### Что считается «ответом»

Один ответ ассистента в чате — один вызов GigaChat, если нет попадания в Redis-кэш (`CHAT_RESPONSE_CACHE_ENABLED`, TTL `CHAT_RESPONSE_CACHE_TTL_SECONDS`). Повтор с тем же вопросом, контекстом и хвостом истории (`CHAT_RESPONSE_CACHE_HISTORY_CHARS`) не вызывает модель: **0 токенов и 0 ₽ COGS**. Генерация файлов в разделе «Документы» (шаблоны DOCX/PDF) LLM не использует; черновик документа в чате идёт через тот же вызов, но с более длинным completion.

### Параметры оценки (текущая архитектура)

| Параметр | Значение | Комментарий |
|----------|----------|-------------|
| Токенов на ответ (консультация) | ~2900 | сжатый RAG, system prompt, история, короткий ответ |
| Токенов на ответ (документ в чате) | ~3700 | тот же prompt, длиннее JSON/текст документа |
| Смесь 85% / 15% | **~3020** | рабочая оценка «среднего» ответа |
| Доля кэша | 0% / 20% / 30% | 20% — базовый сценарий до накопления факта в проде |
| Ответов в месяц | 8 / 25 / 80 | лёгкий / средний / активный профиль |

Тариф меняется через `GIGACHAT_PRICE_PER_1K_TOKENS` в `.env` или `backend/app/core/config.py`.

### COGS LLM, ₽ на пользователя в месяц

Смесь **~3020** токенов на ответ, `GIGACHAT_PRICE_PER_1K_TOKENS = 0.065`:

| Профиль (ответов/мес) | Без кэша | Кэш 20% | Кэш 30% |
|----------------------|----------|---------|---------|
| Лёгкий (8) | 1,57 | 1,26 | 1,10 |
| Средний (25) | 4,91 | **3,93** | 3,44 |
| Активный (80) | 15,70 | 12,56 | 10,99 |

Ориентир: при **~25 ответах в месяц** и **~20% кэша** LLM COGS **~4 ₽ на пользователя в месяц** (только GigaChat).

**Один платный ответ** при кэше 20%: смесь ~**0,16 ₽**; только консультация ~**0,15 ₽**; только документ в чате ~**0,19 ₽**.

### Фактические данные в продукте

После деплоя с учётом usage события пишутся в `llm_usage_events`; COGS считается в `backend/app/services/llm_cost.py`. В админке: **Статистика** и список пользователей (токены, COGS, попадания в кэш), API `GET /admin/stats`, `GET /admin/cogs`, `GET /admin/users`. Для юнит-экономики по факту смотрите агрегаты по пользователям, а не только таблицу выше.
