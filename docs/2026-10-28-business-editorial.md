# Общая редактура ответов при подготовке документов

Причина: local_candidate считал наличие глагола или короткую фразу достаточным подтверждением официального стиля. Поэтому свободные ответы обходили редактор GigaChat. Булева проверка пакетной редакции также пропускала копирование источника и некоторые добавленные факты.

Изменения:

- Свободные поля всех 38 форм проходят изолированный редактор; готовые точные преобразования списков, реквизитов и однозначных вариантов остаются детерминированными.
- Свободные фрагменты двух специальных компоновщиков используют тот же путь. Их проверенный текст сохраняется при повторной композиции.
- Для фрагментов учитывается окружающее предложение; соседние поля не передаются как материал для заполнения. Точное повторение обрамления шаблона удаляется.
- Проверка отдельно оценивает сохранение смысла, официальный стиль и пригодность для подстановки, с причиной решения. Отклонённая редакция получает повторную попытку с обратной связью. Уже корректный исходник допустим только после проверки.
- Общий механический контроль отклоняет известные разговорные обороты, изменение чисел и дат, приписывание отправки уведомления, неподтверждённую неизвестность и подмену первого лица третьим. Равнозначные числительные для рабочих дней и числа месяца приводятся к исходным цифрам.
- Длинный ответ, который не удалось отредактировать целиком, разбивается на исходные предложения; сборка снова проверяется по полному источнику.
- В трёх потребительских претензиях обрамление поля payment заменено на «Способ возврата денежных средств». Новые неизменяемые DOCX-ресурсы имеют версию 9. Правовые нормы не менялись.
- EDITOR_VERSION = 13 отменяет старые редакции, кэш и повторное использование старых экспортов. Исходные ответы остаются в fields.

Проверка:

- 490 тестов: tests/test_document*.py, test_complete_document_forms.py, test_rental_editorial_flow.py, test_business_editorial.py. Все прошли.
- Настоящий GigaChat: претензия по просрочке доставки дивана, договор услуг, иск по займу. Последний прогон — без form_review_fields во всех трёх случаях.
- Итоговые три DOCX заполнены настоящим механизмом OOXML и просмотрены на всех шести страницах. LibreOffice отсутствует, поэтому PDF для проверки получены скрытой автоматизацией Word и отрисованы pypdfium2.
- API перезапущен; сайт и /api/health возвращают HTTP 200.

Воспроизведение проверки GigaChat: backend/tests/business_editorial_qa_manual.py. JSON с исходными и итоговыми полями сохраняется в backend/tests/business-editorial-qa. tools/fill_business_editorial_qa.py заполняет тестовые DOCX с вымышленными реквизитами.

Ограничения: модель остаётся вероятностной; это не доказательство качества любого возможного диалога. Если редакцию не удалось подтвердить, существующий механизм оставляет подписанное поле для проверки, а не вставляет отклонённую редакцию. Ранее скачанные DOCX не изменяются; для проверки нужна новая подготовка файла.
