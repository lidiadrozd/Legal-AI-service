# Опрос по смыслу полей шаблона

В рабочие API создания документа и сообщений подключён conversational_interview_turn. Детерминированный контроллер отвечает за проверку и сохранение фактов; отдельный планировщик GigaChat выбирает следующее активное незаполненное поле и самостоятельно формулирует вопрос.

Планировщику не передаётся поле question из заранее написанной анкеты. Он получает смысл, тип и допустимые варианты поля, границы данных, известные факты, запрос и реальную историю разговора. Техническая резервная реплика контроллера удаляется перед формированием контекста и перед сохранением ответа модели. Имена и адреса — отдельные вопросы. Неправильный field, повтор заполненного поля, объединение имени с адресом, несколько вопросов и служебные маркеры отклоняются. Для неудачного плана есть повторная попытка. Если план не подтверждён, пользователь видит честное сообщение о недоступности следующего вопроса и может написать «повтори»; готовая анкета не подставляется скрытно.

Исходные явно сообщённые сведения извлекаются отдельным ограниченным шагом: сохраняется только точная цитата из пользовательского запроса, прошедшая существующую проверку поля. GigaChat не меняет структуру документа и перечень обязательных данных. «Например», «пример», «конкретно какие» обрабатываются как просьба пояснить текущий шаг и не записываются в документ. Пояснение не должно приписывать пользователю отпуск, выплаты или другие условия из выдуманного примера.

В трудовой форме убраны указания «для школы», «для учителя», примеры предметов и классов из общих вопросов. Отдельная педагогическая нагрузка — условное и необязательное поле; её отсутствие можно указать явно. Условная строка не появляется при ответе «нет». Активная версия ресурса — 5, схема — 2; прежние чаты получают актуальную схему через существующую миграцию.

Дополнительно исправлены обычное «основная» как вариант основной работы, команда «продолжить» и явная адресная поправка с удалением названной квартиры и добавлением города без потери улицы и дома. Факты остаются отделены от сформулированных вопросов и будущей редакции документа.

Проверка: общий набор — 542 теста; после уточнения границ полей — ещё 8 целевых проверок планировщика и восстановления контекста. Настоящий GigaChat успешно сформулировал вопросы для договора детского сада с воспитателем, договора организации с бухгалтером и потребительской претензии. Это проверка конкретных сценариев, а не доказательство качества любого будущего разговора.

Основные файлы: document_conversation.py, API chat.py и documents.py. В pytest формулировщик явно отключён от сети; тесты планировщика задают свой provider. conversation_planner_qa_manual.py проверяет настоящий сервис без тестового отключения сети.
