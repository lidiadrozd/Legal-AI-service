# Библиотека форм и границы автозаполнения

Обновлено 26 октября 2026 года.

## Что хранится

В `backend/app/templates/form_sources/` сохранены 71 исходный документ:
63 PDF с официального сайта Нижегородского областного суда и 8 публичных
ознакомительных DOCX ARRJ. У каждого есть ссылка, издатель, дата получения,
SHA-256 оригинала, извлечённый текст и его SHA-256. Это справочные источники,
а не 71 готовая и юридически проверенная форма автозаполнения.

Ссылки на каталоги:

- https://nnoblsud.ru/index.php/spravochnaya-informatsiya
- https://arrj.ru/shablony

Старые судебные образцы требуют проверки действующего законодательства.
Публичная доступность коммерческого ознакомительного DOCX не означает права
на его перепубликацию. Оригиналы ARRJ используются для внутренней сверки
структуры; выдаваемые пользователю тексты составлены самостоятельно.
Некоторые исходники содержат демонстрационные реквизиты и условия.

## Как выбирается форма

1. Явно запрошенный вид документа ограничивает допустимые сценарии.
   Договор не может быть заменён претензией по похожей теме аренды.
2. Для конкретного сценария загружается полный версионированный JSON с
   блоками документа. Внешний опрос хранится в `templates/intake/`.
3. RAG извлекает справочные фрагменты только из источников, явно сопоставленных
   с этим сценарием в манифесте. Общая близость слов не даёт такого разрешения.
4. В состоянии диалога сохраняются сценарий, версия, хеш выбранного пакета
   и источники. Вопросы и окончательный файл используют одну структуру.
5. Реквизиты и примеры исходного образца не становятся фактами пользователя.
   В справочных фрагментах маскируются числовые примеры и типичные ФИО.
6. Неподдерживаемый договор требует уточнения; модель не выбирает вместо
   него ближайшую претензию. Наличие исходника в каталоге не включает его
   автозаполнение без адаптера.

Каталог источников доступен авторизованному пользователю через
`GET /documents/form-sources?q=...&document_kind=contract`.
Ответ содержит метаданные, без полного текста и демонстрационных реквизитов.

## Текущее покрытие

В приложении 33 сценария. Шесть имеют подробную структуру с проверкой вывода
всех активных полей: иск о заливе квартиры, наём жилья, услуги, подряд,
заём и жалоба в Роспотребнадзор. Остальные 27 используют прежние базовые
формы. Это явно отражено в `docs/document_schema_audit.json`.
Не следует называть их столь же подробными или юридически проверенными.

Восемь исходных форм явно сопоставлены с четырьмя сценариями: залив,
иной имущественный ущерб, защита потребителей и наём жилья. Остальные
исходники доступны для поиска и последующей подготовки адаптеров.
Официальные рекомендации Роспотребнадзора указаны непосредственно в пакете
жалобы. Сведения о проверке юристом остаются пустыми, пока такая проверка
фактически не проведена.

Для нового адаптера необходимо отдельно определить роли, условия применения,
существенные сведения, вопросы, ветвления и полный текст с заполнителями.
После этого проверяются соответствие полей и блоков, отсутствие чужих
примеров, полный диалог, выдача файла и страницы DOCX. Скачать образец
недостаточно для автоматического включения в продукт.

## Редакция и файл

Исходные ответы остаются неизменными. Отдельный редактор обрабатывает
только текущий фрагмент. Числа и даты защищены маркерами; проверяются
неизменность ролей, реквизитов и отсутствие новых событий или требований.
Исходное первое лицо сохраняется. После редактирования проводится отдельная
проверка смысла и стиля. Если модель испортила уже корректный исходный текст,
его можно использовать только после явного одобрения этой проверкой.
Сетевой сбой не разрешает выдачу непроверенного разговорного текста.

Структура, заголовки, абзацы, нумерация приложений, подписи и страницы
собираются кодом. Неизвестные реквизиты остаются подписанными заполнителями.
Обновление схемы старого чата возвращает недостающие вопросы. При исправлении
неверного вида документа ответы архивируются, а факты старого спора не
становятся условиями нового договора.

## Проверка и восстановление

- `tools/audit_document_schemas.py`: аудит 33 сценариев.
- `backend/tests/test_document_form_library.py`: выбор вида, миграция,
  адреса, срок, неизвестные сведения, изоляция источников, хеши, стиль.
- `backend/tests/live_form_library_manual.py`: полный опрос по найму и жалобе
  с настоящим GigaChat на вымышленных данных, создание DOCX; запуск вручную.
- `tools/create_checkpoint.py`: снимок кода и библиотеки без секретов,
  пользовательских загрузок и базы. Оригиналы библиотеки включены в снимок.

Снимок до обновления: `artifacts/checkpoints/document-forms-2026-10-25-before-rag-library.zip`.
Проверенный снимок: `artifacts/checkpoints/document-forms-2026-10-26-verified.zip`.
Рядом сохраняется SHA-256. Восстанавливать следует в отдельную папку,
сначала проверив манифест; текущие данные пользователей не заменяются.
