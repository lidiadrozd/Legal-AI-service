## Контракт

- `document_scenarios.Field` задаёт вопрос, тип значения, варианты выбора и условия включения поля.
- `field_is_active` используется для выбора следующего вопроса, редактирования и проверки полноты.
- Версия схемы согласуется с JSON-пакетом. Для `coverage=structured` загрузчик проверяет, что содержательные поля анкеты действительно представлены в документе.
- `readiness_report` отделяет отсутствие фактов, юридические вопросы для проверки и невыполненные действия перед подачей. Окончание анкеты не означает готовности документа к подаче.
- Факты, исходный ответ, подтверждение относительного адреса и официальная редакция сохраняются раздельно. Изменение адреса-основания требует нового подтверждения ссылки на него.
- Неудачное редактирование не превращает корректный ответ пользователя в неизвестное поле. Проверенные фрагменты сохраняются для повторной подготовки.
- Общение остаётся по одному вопросу; пояснение возвращает к текущему шагу. Текст документа не подменяет скачиваемый файл.

## Переведённый сценарий

`claim_damage_flood`, версия 2: отдельные реквизиты сторон, адрес повреждённой квартиры, основание права, дата и источник залива, связь ответчика с источником, повреждения, варианты восстановления, расчёт и доказательства, досудебные действия, судебные расходы, условные просьбы об экспертизе и обеспечении, направление копий, приложения и подписант.

Указание «собственник», заключения эксперта, причины происшествия и размеры расходов не выводятся из предположений. Формулировка «решить проблему» требует уточнения конкретного действия. Суд, подсудность и пошлина при отсутствии проверенных сведений остаются вопросами проверки, а не заполняются догадками.

Нормативные ориентиры: ГК РФ, статьи 15 и 1064; ГПК РФ, статьи 131 и 132. Ссылки и дата сверки хранятся в пакете. Это самостоятельная структура, а не скачанная или лицензированная копия конструктора ГАРАНТа. `source_checked_draft` и `coverage=structured` не означают юридического одобрения.

## Остальной каталог

Запуск: `.venv/Scripts/python.exe tools/audit_document_schemas.py`.
Результат: `docs/document_schema_audit.json`, все 33 сценария, семейства, версии, структурные ошибки, условные поля и вопросы без прямой подстановки в текст.

32 остальных сценария сохраняют статус `basic`. Они не объявляются полноценно проверенными: при выдаче файла пользователь получает соответствующее сообщение. Их поэтапный перевод требует содержательной сверки каждого вида документа, а не автоматического присвоения статуса по успешному прохождению технических тестов.

Для каждого следующего сценария: сверить актуальные требования и варианты → обновить поля и блоки вместе → проверить неизвестные сведения и смену вариантов → пройти весь диалог, создание и скачивание DOCX → проверить страницы → сохранить источники и фактический статус проверки.

## Проверки

`backend/tests/test_document_structured_schema.py` покрывает относительные адреса, смену адреса-основания, ветки ремонта/экспертизы, нечёткие требования, полноту схемы, сбой редактора, содержание и скачивание реального DOCX через API.

`backend/tests/live_document_schema_manual.py` — отдельная проверка настоящего GigaChat на вымышленных данных. Результаты находятся в `backend/tests/schema_qa/`. Не запускается автоматически и не изменяет пользовательские чаты.

Визуальная проверка: при отсутствии bundled LibreOffice использован скрытый Word через `tools/render-word-preview.ps1`, затем просмотр PNG всех страниц. Наличие файла или успешные тесты не заменяют просмотр страниц.

Проверено 25.10.2026: 195 автоматических тестов прошли в контейнере приложения; полный опрос на вымышленных данных с настоящим GigaChat завершился за 31 ответ с созданием DOCX; окончательный образец занимает две страницы, обе просмотрены. Отдельная проверка API создала, сохранила и скачала DOCX, сохранив отчёт о недостающих сведениях. Существующие предупреждения библиотек об устаревших API не связаны с этой доработкой.
