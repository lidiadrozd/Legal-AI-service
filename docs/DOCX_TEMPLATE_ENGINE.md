# Эталонный DOCX и сохранение оформления

Включено для `contract_housing`, версия текстового пакета 4. Опрос остаётся
версии 2: перечень, порядок вопросов и разговорный промпт не менялись.
Другие формы продолжают использовать прежний экспорт, пока для них не
подготовлен собственный эталон.

## Состав пакета

`backend/app/templates/assets/contract_housing/v4/`:

- `template.docx`: самостоятельно подготовленная форма с OOXML content controls.
- `schema.json`: поля, форматы значений, условия и правила подпунктов.
- `reference.pdf`: контрольное представление формы с подписанными пустыми полями.

`templates/documents/contract_housing.json` связывает сценарий с DOCX и схемой,
фиксирует их SHA-256 и версию. Подмена файла или выход за папку assets
блокируют экспорт. В RAG остаются текст и метаданные выбранной формы;
поисковые фрагменты не задают вёрстку.

## Экспорт

Сервис `document_docx_template.py` открывает эталон и подставляет проверенные
значения в помеченные поля. Исходные ответы хранятся отдельно и не меняются.
Сохраняются стили, параметры страницы, табуляция, таблицы, подписи и свойства
абзацев. Условные блоки удаляются целиком; длинные перечисления становятся
настоящими абзацами с нумерацией из схемы. В готовом файле content controls
разворачиваются в обычные редактируемые абзацы и runs, чтобы документ также
читался стандартными средствами извлечения текста.

В версии 4 названия групп внутри ответственности сторон выводятся жирными
ненумерованными подзаголовками и удерживаются рядом со следующим абзацем.
Номер получают только условия. Проверки словоформ в описании жилья и
восстановление обрезанной фразы о месячной плате по исходному ответу применяются
также к ранее сохранённой редакции. Исходные ответы не переписываются.

DOCX/PDF получают один набор данных и один эталон. PDF конвертируется из
заполненного DOCX через LibreOffice с отдельным временным профилем, без
второй независимой сборки в ReportLab. В API конвертация выполняется вне
цикла обработки запросов. При сбое конвертации не выдаётся PDF иной вёрстки.
Docker-образ содержит LibreOffice Writer и Liberation fonts.

Ссылки вида «пункт X/Y» из пользовательского примера показываются как
`[номер пункта]` и отмечаются среди сведений для проверки. Новые номера
пунктов не угадываются. Незнание реквизитов не подменяется данными образца.

## Проверки

- `backend/tests/test_document_docx_asset.py`: сохранение секций/стилей/таблиц,
  подстановка и экранирование текста, реальные абзацы, ветки платежа,
  неизвестные поля, целостность активов, выдача через API и общий путь PDF.
- `backend/tests/live_housing_docx_asset_manual.py`: реальный экспорт обоих
  форматов из сохранённого интервью с проверкой неизменности исходных фактов.
- `tools/build_housing_docx_asset.py`: однократная подготовка эталона;
  не вызывается во время заполнения пользователем.
- `tools/preview_housing_docx_asset.py`: короткий, длинный и пустой варианты
  для визуальной проверки страниц. Изменение эталона требует повторного
  рендера и сравнения DOCX/PDF.

Эталон задаёт оформление продукта. Он не является утверждённой государством
универсальной формой или подтверждением проверки юристом; статус юридической
проверки остаётся отдельно в метаданных.
